#### ⚠️ 发现的问题及修复

##### 问题1: IPv6地址的AS号查询失败

**现象**：
```python
# IPv6地址查询时，GeoIP2数据库可能返回空结果
geo_info = geo_service.query_ip("2001:db8::1")
# 返回: {}
```

**影响**：
- AS号字段为空
- 降低置信度评分

**解决方案**：
- ✅ 已在代码中处理：当geo_info为空时，跳过该跳点的AS号填充
- ✅ 不影响其他维度的特征提取（Hostname、IP段、RTT仍可用）

**建议优化**：
- 未来可集成支持IPv6的GeoIP数据库
- 或在文档中说明当前对IPv6的支持限制

---

##### 问题2: 极端RTT值可能导致误判

**现象**：
```python
# RTT从0.001ms突增到999.999ms
hop_1.rtt = 0.001
hop_2.rtt = 999.999  # 可能是测量误差或网络抖动
```

**影响**：
- 可能被误判为WAN出口
- 但实际上可能是临时网络拥塞

**解决方案**：
- ✅ 当前实现已考虑：需要结合其他证据（IP段、Hostname）综合判断
- ✅ 单一RTT突变权重较低（2分），不足以单独决定CPE位置

**建议优化**：
- 可增加RTT稳定性检查（多次测量取平均）
- 或过滤掉明显异常的RTT值（如>500ms）

---

##### 问题3: 全私网路径的置信度过低

**现象**：
```python
# 所有跳点都是私网IP（192.168.x.x）
hops = [
    {"ip": "192.168.1.1"},
    {"ip": "192.168.2.1"},
    {"ip": "192.168.3.1"},
]
# 结果: confidence=0.2, mode=unknown
```

**影响**：
- 纯内网环境难以准确识别CPE
- 用户可能得不到有用的诊断信息

**解决方案**：
- ✅ 当前实现：返回低置信度结果，并在日志中警告
- ✅ 建议在UI中提示用户"内网环境，建议人工确认"

**建议优化**：
- 可增加内网专用规则（如识别网关设备的常见IP段）
- 或要求用户提供网络拓扑图辅助判断
